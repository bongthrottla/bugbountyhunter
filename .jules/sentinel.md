## 2025-02-26 - [Local Information Disclosure via Insecure File Permissions]
**Vulnerability:** The application was creating local output directories (scans, outputs, reports) and files without explicitly setting file permissions, resulting in the default umask being applied. This could potentially expose sensitive bug bounty scan results, reconnaissance data, and comprehensive reports to other local users on the same system.
**Learning:** In desktop applications that handle sensitive information (like penetration testing tools), default file permissions are often too permissive. Relying on the user's OS defaults (umask) can inadvertently leak sensitive findings (such as XSS payloads, discovered vulnerable endpoints, etc.) to any other local users.
**Prevention:** Always explicitly set restrictive file permissions when creating directories or files that will contain sensitive data. For directories, apply `os.chmod(directory, 0o700)`. For files containing sensitive reports, apply `os.chmod(file, 0o600)` to ensure only the owner has read and write access.
